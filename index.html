How I build in the AI era

Generic chat windows won't ship apps; custom tooling, context engineering, and native craft will. Six principles I've sharpened across 11+ years of native Apple work — and rewired around AI in the last two.

01

AI is leverage,
not a replacement.

Claude Code and Copilot run end-to-end through my dev cycle — but architectural judgment, HIG fidelity, and concurrency safety stay human. I mentor pods on when to accept AI output and when to course-correct. The senior engineer's job didn't go away; it changed shape.

Daily practice · Scotiabank pod
02

Custom skills beat
generic prompts.

I author team-wide Claude skills that connect to Figma (MCP), JIRA, BitBucket, and Swift Package Manager — so the model sees the same shape of work my team does. Generic chat windows don't scale; bespoke tooling does. The 10× moment comes from building for AI, not just prompting it.

Shipped · MCP integrations
03

Context engineering
> prompt engineering.

The bottleneck in 2026 isn't writing prompts — it's piping the right context to the model. My Chrome extension compresses Confluence specs from 14k tokens to 2.1k and feeds the model what's load-bearing. The skill is knowing what to leave out.

Shipped · Confluence + JIRA → AI
04

Native craft compounds
with AI velocity.

SwiftUI, Combine, Swift Concurrency, @Observable, Apple HIG — none of this goes away when AI writes the code. It's what makes AI output safe to ship: easier to review, harder to break in concurrency, and aligned with the platform users already trust. Craft is the moat.

Apple HIG · 11+ years
05

Test the output.
Don't trust it.

TDD, XCTest, AI-driven PR review against a real CI gate. Anything AI generates earns the same scrutiny a junior PR would — usually more, because the failure modes are different (plausibly-correct compile errors, silent concurrency bugs, hallucinated APIs). Trust nothing the test suite hasn't seen.

Quality bar · TDD · CI gates
06

The future is composable,
multi-platform, on-device.

visionOS, App Intents, Dynamic Island, on-device foundation models, Live Activities. The job stops being "iOS" — it's native experiences across every Apple surface, AI woven through each one, increasingly running on the user's silicon. That's where my work lives, and where the next 5 years of Apple-platforms hiring will live too.

Forward bet · all six platforms

LaunchSim — “The Simulator IDE.”

A native macOS app that turns iOS / tvOS / watchOS / visionOS simulators (and physical devices) into a composable debug workbench. Pick a simulator + app, tile up to six tools, and reach for the things Xcode hides: UserDefaults, keychain, sandbox, network capture, permissions, logs, location, biometrics, notifications, accessibility, and a dozen more — 17 feature modules in total. Ships with built-in templates (Auth Debugging, Push Testing, UI Polish, Data Debugging) and session recording via simctl io recordVideo with auto-export.

Engineered as a 4-layer SPM monorepo — Core / UI / Workbench / 17 Feature packages — with a strict no-cross-feature-import rule. ViewModels are @Observable @MainActor (no Combine). Physical-device support is wired via devicectl JSON + IOKit USB hot-plug notifications. The companion LaunchSimSDK swizzles URLSession and registers a URLProtocol to capture network traffic from any embedding app. Shipped as a signed .dmg with a Sparkle appcast and a beta gate.
